Developer API

Every observation this site displays is available as JSON over HTTPS. There is no API key and no registration — just a generous rate limit described below. The feeds are static files served from a CDN edge, so they are fast and cheap to read.

Base URL
https://halibutbank.ca/api/v1

GET /api/v1/ returns a machine-readable catalog of every endpoint below, including its refresh interval and cache lifetime, so you can discover the surface programmatically rather than hard-coding this page.

Quick start

curl -s https://halibutbank.ca/api/v1/buoys/latest

Cross-origin requests are allowed from any origin, so browser code works directly:

const res  = await fetch("https://halibutbank.ca/api/v1/buoys/latest");
const data = await res.json();

const halibutBank = data["4600146"];
if (!halibutBank.stale) {
  console.log(`${halibutBank.wave_height_sig} m @ ${halibutBank.wave_period_peak} s`);
}

Valid {id} values for the wave forecast endpoints are 4600146, 4600206, 4600304, 46087, 46088, and CRPILE. Read /wave-forecast rather than hard-coding that list — stations get added.

Reading the data correctly

Directions are meteorological

Every direction field is the direction the wind or waves are coming from, in degrees true. A wind_direction of 90 means an easterly — wind blowing from the east toward the west. Getting this backwards is the single most common mistake with marine data.

Check stale, not the timestamp

Observation payloads carry a stale boolean and an age_minutes value. Instruments drop out regularly — buoys go offline for maintenance, upstream feeds gap — and a payload will happily hand you a three-day-old reading with a perfectly valid timestamp. Freshness is evaluated per field over a two-hour window. Always branch on stale.

Every wind speed is in knots

All of them, on every endpoint, with no exceptions. Wind is stored internally in km/h and converted on export, so nothing published here is km/h.

The field names are less consistent than the units are. Some endpoints say wind_speed_kt and others just say wind_speed — that is naming history, not a unit distinction, and it is the one thing on this page most likely to cost you an afternoon. If you see a bare wind_speed and assume it must be km/h because a neighbouring endpoint bothered to write _kt, you will convert a 15-knot wind into 8 knots.

Every wind speed now also has an explicit _kt name. Prefer the _kt fields in new code. The bare names remain, and will keep working and keep meaning knots, but treat them as the legacy spelling. /wind/timeseries returns bare arrays of numbers and publishes a _meta.units map describing them.

Other units: wave heights and water levels are metres, temperatures Celsius, pressures hectopascals. A pressure near 999 hPa is a real reading, not a missing-value sentinel.

Timestamps are UTC

All times are ISO 8601 with an explicit UTC offset, e.g. 2026-08-27T17:05:00+00:00. Local time on the water is America/Vancouver, which observes daylight saving.

Caching and fair use

This runs on a single home server behind a CDN. Responses carry Cache-Control headers matched to how often the underlying data actually changes, and an ETag you can use with If-None-Match for cheap conditional requests.

Polling faster than the refresh interval returns identical bytes. /buoys/latest updates every three minutes; requesting it every second gets you the same payload 180 times. Please poll at or below the listed rate, and send a descriptive User-Agent so I can reach you if something you depend on is about to change.

There is one hard limit, enforced at the CDN edge: 100 requests per 10 seconds per IP address, across all /api/ paths combined. Exceeding it returns 429 Too Many Requests for the following ten seconds, after which normal service resumes on its own — there is no lasting ban and nothing to appeal. Polling at the documented intervals will never come close. If you have a use case that legitimately needs more, get in touch.

Stability

The /api/v1 prefix is a contract. Within v1, fields may be added, but existing field names and their meanings will not change and endpoints will not be removed or renamed. Anything breaking gets a /api/v2. Note that the underlying file paths under /data/ are not part of that contract — they are internal and do change. Build against /api/v1.
