# ==================== BACKUPS & MAINTENANCE ====================
# Backup crontab to repo (07:15 UTC, before git backup) — validates first; on
# missing scripts, dumps to config/crontab.txt.broken-<ts> and leaves canonical
# untouched so the auto-commit below won't pin a broken state.
15 7 * * * /home/keelando/envcan_wave/scripts/backup_crontab.sh >> /home/keelando/envcan_wave/logs/crontab_backup.log 2>&1

# Git auto-backup - envcan_wave repo (07:17 UTC / 12:17am PT). Runs pre-commit
# hooks (no --no-verify); if tests fail, commit aborts and the working tree
# retains the staged changes for next run / manual review. Also mirrors main to
# the local Forgejo backup (survivor.local) unconditionally — separated by ';'
# so a down Forgejo never blocks the origin push, and vice versa.
17 7 * * * cd /home/keelando/envcan_wave && { /usr/bin/git add -A && /usr/bin/git diff --staged --quiet || (/usr/bin/git commit -m "Auto-backup $(date +\%Y-\%m-\%d)" && /usr/bin/git push origin main) ; /usr/bin/git push forgejo main --tags ; } >> /home/keelando/envcan_wave/logs/git_backup.log 2>&1

# Sync venv with the pinned lock file (07:18 UTC / 12:18am PT, after git
# backup). Installs from requirements-lock.txt, not pyproject.toml, so
# transitive versions are pinned too and a rebuilt venv can't drift.
# Near-always a no-op; --disable-pip-version-check keeps the log to real work.
18 7 * * * /home/keelando/envcan_wave/.venv/bin/pip install -q --disable-pip-version-check -r /home/keelando/envcan_wave/requirements-lock.txt >> /home/keelando/envcan_wave/logs/pip_sync.log 2>&1

# ==================== COOKIE CLICKER ====================
# Moved here from survivor 2026-08-08 (survivor was under load); the survivor
# crontab line is commented out there, not deleted.
#
# The container leaks memory. daily-restart.sh is GUARDED: it takes a save via
# backup.sh FIRST and restarts only if the save succeeded, because a restart is
# exactly when an unflushed save is lost. On a failed save it logs SKIP and
# leaves the container running.
#   => A persistently broken backup.sh silently disables the restart.
#      projects/cookie_clicker/restart.log is where that shows up, and it is the
#      file to check if memory starts climbing again.
#
# 13:29 UTC / 06:29 PT. The minute matters: on survivor this job failed silently
# for five days when it collided with the restic backup. 29 is clear of every
# other minute pattern in this file, and 13:29 is well clear of restic at 10:33.
# UNPARKED 2026-08-17 -- the lag is SOLVED. The container had no GPU in it.
# Passing /dev/dri/renderD128 through (plus group_add 993/44, the host render
# and video gids) fixed it. Note this was a LATENCY fix, not a throughput one:
# the GPU sits at its 300 MHz floor even while streaming, because all it had to
# do was take compositing off the software path. That is why the 2026-08-09
# measurements found the box 91% idle and lagging at the same time and could
# not reconcile them.
# Re-enabled only after the backup was proven END TO END on 2026-08-17: the
# scraped save-20260817.txt was imported into a throwaway container and
# restored 1271 buildings / 78 achievements / 586T cookies from a blank game.
# The file is a plain Cookie Clicker export string -- restoring is pasting it
# into Import Save.
# See homelab hosts/surfserver/hat-5-cookie-clicker.md.
